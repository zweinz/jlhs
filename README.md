# SF Hiding Area

A responsive React + TypeScript + Vite browser application that models San Francisco geographic-question answers as GeoJSON with Turf, then displays them with the Google Maps JavaScript API. Question/answer models and geometry live outside the renderer.

## Local development

Requires Node.js 20+. The checked-out local installation lives at `~/Sites/jlhs`. Copy `.env.example` to `.env`. Add a Google Maps JavaScript API browser key restricted to your development and production origins, a separate server key restricted to Routes API, Street View Static API, and Places API (New), a server-only Gemini key, and a random Solo-session secret containing at least 24 characters. Credentials are ignored by Git. Never prefix the Gemini key with `VITE_` or place it in client state.

```bash
cp .env.example .env
npm install
npm run dev
```

Open the Vite URL. Without a key the app deliberately shows an actionable error state. Vite's development middleware mounts the same `/api/*` handlers used in production, so shortened-map-link resolution and Solo mode work on the same local origin. Run tests with `npm test`, produce an optimized bundle with `npm run build`, and inspect it locally with `npm run preview`.

## Deployment

The production deployment uses Vercel's free Hobby tier. Import the GitHub repository, keep the detected Vite settings (`npm run build`, output directory `dist`), and add `VITE_GOOGLE_MAPS_BROWSER_API_KEY`, `GOOGLE_MAPS_SERVER_API_KEY`, and `SOLO_SESSION_SECRET` for Production, Preview, and Development. Because the browser key is public, protect it with Google Cloud HTTP-referrer restrictions for `http://localhost/*`, `http://127.0.0.1/*`, the production Vercel origin, and preview deployments, plus an API restriction to Maps JavaScript API. Restrict the server key to Routes API, Street View Static API, and Places API (New). During secret rotation, temporarily set `SOLO_SESSION_SECRET_PREVIOUS` so active sessions remain readable for their 48-hour lifetime.

## Data and architecture

`src/data/sf-pois.json` contains 3,760 complete geographic records from the SF workbook at spreadsheet `1VyhjPUGxNSybxBV7yFSEECI9sKcdJOME2TpFpAaXpok`, gid `252568279`, captured 2026-08-24. It covers every source tab containing geographic records; nine unfinished rows in the explicitly WIP stairway tab are recorded as skipped because they have no coordinates. Each POI retains its source sheet, row, object ID, coordinate source, and a stable `sf:<category>:<source-object-id>` identifier. Runtime validation rejects duplicates, malformed IDs, missing provenance, nonnumeric coordinates, and points outside the SF working bounds. Update the checked-in snapshot rather than fetching mutable spreadsheet data in a visitor's browser.

`src/questions.ts` keeps each question family’s rulebook notes, game modifications, answer window, hider-card draw/keep instruction, and source page separate from rendering. Each question’s notes are collapsed by default behind an accessible chevron disclosure. `src/rulebook.ts` inventories every Matching, Measuring, and Photo subject and marks each as in play or excluded from the SF deck; experimental question subjects are not offered. `src/types.ts` separates definitions and answers; `src/geometry.ts` implements radar circles, true start/end thermometer bisectors, nearest-category measuring, seeker-pin Bay/Pacific coastline comparisons, matching regions, tentacle reach, transit-line matching, directional half-planes, intersections, and exclusions. POI-backed partition layers include mountains, dog parks, golf courses, museums, movie theaters, libraries, hospitals, foreign consulates, and farmers markets. They start off, are mutually exclusive, and show numbered source pins with a matching in-panel key. `src/share.ts` validates and version-controls URL payloads before restoration.

`src/data/transit-routes.json` is a normalized, simplified snapshot of the public-domain DataSF **Muni Simple Routes** dataset. The F/J/K/L/M/N/T light-rail lines and 5R/9R/14R/28R/38R Rapid Muni lines remain one map toggle; every other current Muni route is available under a separate, initially-off “Other transit” toggle. `src/data/coastline.json` is derived from the public-domain DataSF **SF Shoreline and Islands** dataset; it keeps the mainland shoreline and removes the straight southern county boundary. `src/data/rulebook-areas.json` adds current Supervisorial Districts, 27 merged DataSF ZIP-code areas, named DataSF water bodies, and the three SF-defined landmasses. ZIPs are correctly described in the UI as generalized delivery-route areas rather than official administrative units. `src/data/sf-elevation-grid.json` and `src/data/sf-street-grid.json` are compact, approximately 300-foot lookup grids derived from Mapzen Terrain Tiles and active DataSF street centerlines. `scripts/normalize-map-data.mjs` and `scripts/generate-sf-grids.py` document the reproducible transformations from downloaded source snapshots.

The 193 spreadsheet-defined stations have touch-friendly markers and configurable hiding-zone radii (default 0.25 miles). One station, all stations, or an entire route can be marked in/out, and every question can be enabled or disabled in one action. The persisted transit-game scope can show all transit or reduce the entire interface and map to the 97 light-rail/Rapid stations and 12 core routes. Station availability updates automatically: a station turns off as soon as its hiding-radius zone has no overlap with the current feasible area. Transit lines identify themselves when tapped. The internal station regions remain available for matching calculations but are never rendered as a partition layer. Area shading defaults to transparent allowed/red excluded and can be switched to green allowed/transparent excluded; the choice is preserved in share URLs.

## Sharing and accessibility

**Share** serializes only map-affecting state into a compact version-4 `?config=` URL and uses the native device share sheet when available, with clipboard fallback. Version-1 through version-3 links still restore safely. Version 4 keeps active geographic constraints, known map-layer bits, transit eligibility, viewport, shading, station-zone radius, transit scope, and any visible or applied manual boundary. It omits pasted Maps URLs, custom question names and IDs, drafts, disabled questions, photo/end-game records, player mode, and all private or transient state; canonical pin links and display labels are regenerated after restoration. Coordinates, boundary paths, station statuses, and route statuses use compact numeric or binary encodings. Invalid or oversized payloads are rejected.

Every pin field accepts full or shortened Google Maps location links, includes an in-field × clear action, and can use the device’s current location with browser permission. Full links are parsed in the browser; `/api/resolve-map-link` follows only allow-listed Google Maps short links and returns the shared pin coordinates. Address-only redirects use the free, keyless U.S. Census geocoder, while arbitrary resolver hosts remain blocked. The layout is mobile-first: the map is placed before the controls on small screens, controls use touch-sized targets, and long layer/legend sections collapse. Hiding-zone radii are initially hidden and can be enabled from the transit layer panel.

Hider mode accepts a Google Maps pin or browser geolocation and calculates answers for radar, thermometer, all in-play SF measuring subjects (including Sea Level, Body of Water, and Coastline), all mapped matching subjects, and tentacles. It does not silently write those calculated answers into the seeker state. Its local path tracer lets a hider tap a street/path from intersection to intersection, undo points, see live feet/miles, and fit the result. A trace-only Screenshot view blanks the basemap and suppresses every other application layer so the result can be captured without revealing the location; the path is intentionally excluded from shared URLs. Photo questions retain their exact framing/content notes but do not otherwise produce a geographic polygon.

## Solo mode

Solo mode is launched from the compact header menu and temporarily replaces the player switch while preserving the prior human workspace. The AI hider is named Xeno. Three approximate no-hide regions extrapolated from the SF game document—Tenderloin/Civic Center, central SoMa, and southeast SF—are expanded by a 300-foot safety buffer and removed from the feasible area and station pool in every game mode. They can be inspected with the off-by-default “No-hide zones” partition layer, which intentionally has no name pins. Solo additionally enforces them for Street View, Move, and Distant Cuisine selection. The selected transit game scope is frozen when the game starts, including for later Move relocations. A Vercel Edge endpoint checks the remaining all-transit or light-rail/Rapid station pool with Google Routes in transit-matrix batches, verifies that the selected sub-30-minute itinerary contains a real transit leg, and chooses a strategically weighted station with at least three outdoor Street View panoramas inside its quarter-mile zone. Restricted games may use any transit itinerary, but the destination must be in the light-rail/Rapid station pool. The exact current position, itinerary, frozen transit scope, private 100-card deck and hand, card ledger, movement, and reveal state live only in an AES-GCM encrypted, 48-hour session token. Games do not use a location commitment because Move and Distant Cuisine can legally change Xeno’s position; only current version-2 Solo sessions are accepted.

The existing question editor becomes a draft-and-ask flow during Solo play. Unasked drafts never alter the committed map, and ready spatial questions can preview both their positive and inverse result before being asked. Xeno’s response opens a non-scrolling result sheet with the answer first, followed by replacement details, draw/keep counts, and any public card or curse action; normal successful answers do not use toasts or move the map. Discard-and-draw hand cycling, including a Duplicate copy of those cards, resolves only inside the encrypted session and is omitted from response announcements and public play history. Solo setup accepts a 5–180 minute hiding time and preserves the configured 0.05–5 mile hiding-zone radius; both settings drive station routing and hiding-spot coverage. The original start remains marked on the map. Answers remain deterministic. Gemini 3.7 Flash receives only compact sealed-session state plus server-generated legal actions and advises keep/play timing; every result is schema-checked and legality-checked before it can change the game. The complete base deck is shuffled with Web Crypto, repeated rewards are separate draw/keep groups, the hand limit and time-bonus scoring are enforced, and physical curse completion is explicitly honor-system based. Seekers may veto an active physical curse that is unavailable or unsafe; this awards no bonus and rolls back coupled benefits. The server-authoritative game clock can pause and resume, including timed-curse deadlines. Hangman and a deterministic, perfect 21×21 Labyrinth maze are generated locally. GPS or a pasted current-location pin starts the end game inside the current station zone and reveals within 30 meters; a find or resignation opens a final score, statistics, curse/card review, and route summary.

### Gemini spend controls

Solo calls the stateless Interactions API with `gemini-3.7-flash`, `store: false`, low thinking, strict JSON Schema, at most 4,000 input tokens, and at most 1,024 generated tokens including thinking. There are no automatic retries. Each game permits 40 strategy inferences, four per rolling minute, and two Maps-grounded lookups. The sealed ledger uses the January 2027 standard assumptions of $1.50/M input tokens and $7.50/M output tokens, reserves $0.10 for each grounded lookup, and refuses a call whose worst-case reservation could exceed $0.75. The tested maximum is $0.7472. Review these constants in `api/_solo-gemini.ts` whenever [Gemini pricing](https://ai.google.dev/gemini-api/docs/pricing) changes.

For deployment abuse protection, use a dedicated Gemini project and lower its inference quota to 50 requests/day and Maps-grounding quota to 5/day wherever Google Cloud exposes those controls. Project quotas are shared safeguards; the encrypted per-game ledger is the game-level ceiling. See [structured output](https://ai.google.dev/gemini-api/docs/structured-output) and [rate limits](https://ai.google.dev/gemini-api/docs/rate-limits).

## Retrospective transit reachability

The app does not calculate or reveal a “how far the hider could have gotten” boundary ahead of time. The Maximum reach research panel lets seekers draw one or more polygons from their own research, preview edits, and independently control whether the saved boundary constrains the feasible area or is merely visible. Manual regions are included in shared maps and are also saved locally for the current share-URL snapshot so later boundary edits survive refresh without leaking into a different shared map. Starting a new Solo round preserves an existing boundary but disables it until the seekers review it; a hider Move also disables the prior boundary because it describes the previous position.
